# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## на разработку информационной системы «Внутренний библиотечный учет»

### 1. ВВЕДЕНИЕ

**1.1. Цель проекта**
Автоматизация внутреннего учёта фонда библиотеки: централизованное хранение метаданных о книгах, авторах и сопутствующих лицах, предоставление инструментария для поиска и аналитики библиотекарям.

**1.2. Область применения**
Внутренняя система для сотрудников библиотеки. Поддержка одновременной работы нескольких пользователей с аутентификацией.

---

### 2. ТЕХНОЛОГИЧЕСКИЙ СТЕК

**2.1. Frontend**

*   **Фреймворк:** Angular (последняя стабильная версия).
*   **Язык:** TypeScript.
*   **UI:** Angular Material или PrimeNG.

**2.2. Backend**
*   **Язык:** C++20.
*   **Web-фреймворк:** Crow (MIT, header-only).
*   **Асинхронность:** Asio standalone (BSL-1.0).
*   **JSON:** nlohmann/json (MIT, header-only).
*   **СУБД-драйвер:** libpqxx (BSD-2) + libpq.
*   **Type-safe SQL:** sqlpp11 (BSD-2, header-only).
*   **Криптография:** MbedTLS (Apache-2.0).
*   **Хэширование паролей:** libsodium (ISC).
*   **JWT:** jwt-cpp (MIT, header-only).
*   **Логирование:** Plog (MIT, header-only).
*   **Тестирование:** Google Test (BSD-3).
*   **Сборка:** CMake 3.20+.
*   **Компиляторы:** GCC 11+ / Clang 14+.

**2.3. Требования к зависимостям**
*   Все библиотеки должны иметь лицензии, совместимые с BSD 3-clause (MIT, BSD-2/3, Apache-2.0, ISC, BSL, Public Domain).
*   Приоритет — header-only библиотеки.
*   Компилируемые зависимости линкуются статически.
*   Итоговый бинарник должен запускаться на Linux и BSD без дополнительных зависимостей, кроме libc.

**2.4. СУБД**
*   PostgreSQL 14+.

### 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

**3.1. Пользователи (библиотекари)**

*   Регистрация и вход по email + пароль.
*   Пароли хранятся в хэшированном виде (bcrypt через libsodium).
*   Каждая запись в БД содержит поле `added_by` — идентификатор создавшего пользователя.

**3.2. Справочники и сущности (CRUD)**

*   **SECTION (Отделы):** название, индекс ББК.
*   **SERIES (Серии):** название.
*   **AUTHOR / TRANSLATOR / ILLUSTRATOR:** фамилия, имя, отчество. Защита от дублей.
*   **BOOK (Книги):** название, город, издательство, год, том, страницы, ISBN, номер издания, примечание. Статусы: доступна / не доступна, наличие иллюстраций.
*   **SUBWORK (Подработы):** название, привязка к книге и автору.

**3.3. Расширенный поиск**

Поддержка комбинаций критериев:
*   Название книги (полное / частичное совпадение).
*   ФИО автора, переводчика, иллюстратора.
*   Название отдела, серии.
*   Фильтры: год издания, `is_available`, наличие иллюстраций.
*   Пагинация и сортировка результатов.

### 5. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС

*   **Дашборд:** краткая статистика, быстрый доступ к поиску.
*   **Формы:** валидация на клиенте (обязательные поля, формат года/ISBN, длина строк).
*   **Таблицы:** сортировка, пагинация, действия «Редактировать», «Удалить».
*   **Панель поиска:** выпадающие списки для справочников, текстовые поля, динамическое добавление условий.
*   Адаптивная вёрстка (ПК, планшеты) и SPA-подход.

### 6. BACKEND И API

**6.1. REST API**
*   Формат — JSON.
*   HTTP-методы по назначению: GET, POST, PUT/PATCH, DELETE.
*   Группировка по ресурсам: `/api/v1/books`, `/api/v1/authors` и т.д.

**6.2. Архитектура**
*   Гексагональная архитектура
*   Умные указатели, RAII.
*   SOLID

**6.3. Работа с БД**
*   Транзакции через `pqxx::transaction` для атомарности сложных операций.
*   Явное использование `JOIN` в запросах — проблема N+1 решается на уровне SQL.
*   Все параметризованные запросы через prepared statements (защита от SQL-инъекций).

**6.4. Безопасность**
*   Валидация входящих DTO (обязательные поля, форматы, длина).
*   Защита от XSS — экранирование на бэкенде + встроенные механизмы Angular.
*   Все эндпоинты, кроме `/api/v1/auth/**`, защищены JWT-фильтром (HS256/RS256).

### 7. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

**7.1. Производительность**
*   Отклик CRUD ≤ 100 мс.
*   Сложный комбинированный поиск ≤ 2 с.
*   Потребление памяти в простое ≤ 50 МБ.
*   Холодный старт ≤ 500 мс.

**7.2. Логирование**
*   Уровни ERROR / WARN / INFO через Plog.
*   Логирование критических действий пользователей (удаление, смена статусов).

**7.3. Развёртывание**
*   Итоговый артефакт — единый статический бинарник.
*   `Dockerfile` с мультистейдж-сборкой.
*   `docker-compose.yml` для связки: приложение + PostgreSQL + Nginx (для Angular).
*   Миграции БД — Flyway.

**7.4. Качество кода**
*   Модульные тесты на Google Test.
*   Doxygen-совместимые комментарии.
*   Флаги компиляции: `-Wall -Wextra -Werror -Wpedantic`.
